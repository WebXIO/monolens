# Monolens

Open-source MongoDB GUI for the desktop (Apache-2.0, homepage monolens.org). A Tauri 2 app: the Rust core stores connections, keeps passwords in the OS keyring and talks to MongoDB; a Vue 3 web view shows the connection manager, a database/collection explorer and query tabs with a table and a JSON view. It only reads data so far. The project was picked up again in November 2026 after a pause since March 2026.

Read `docs/README.md` first. `docs/architecture/overview.md` has every IPC command and how a query travels, `docs/features/` has one file per feature with its known bugs.

## Repository

Single package, always use pnpm. It is pinned in `package.json` (`packageManager` and `devEngines.packageManager`, 12.17.0); a plain `pnpm` switches to that version. Build scripts of dependencies only run when `pnpm-workspace.yaml` lists them under `allowBuilds`, else `pnpm install` fails. The Rust crate lives in `src-tauri`.

| Path | Content |
|---|---|
| `src-tauri/src` | Rust core: `connector` (saved connections, keyring), `database` (test, connect, list, find commands), `task_manager` (cancellable tasks), `connection_handler` (driver pool), `drivers` (`DatabaseDriver` trait, MongoDB driver) |
| `src` | Vue 3 + Pinia + Tailwind 4 UI: `domains` (models, services, provider registry), `stores`, `components`, `composables`, `utils`, `plugins` |
| `src/components/ui` | shadcn-vue components (`components.json`), generated by its CLI, then owned by the repo |
| `src/utils/queryParser` | The shell-syntax query parser and its vitest tests |
| `docs` | How the app is built and why (English): `architecture/overview.md`, `architecture/decisions.md` (decision log), one file per feature in `features/`. `docs/README.md` has the template of a feature file and the open issues by area |
| `docs/plans` | Researched plans as written before the work, not updated afterwards. Open plans in `docs/plans/`, built ones in `docs/plans/implemented/` with a status note at the top; `docs/plans/README.md` lists every plan with its status. See "Keep in sync" |

GitHub: `github.com/WebXIO/monolens` (public), issues there are the backlog. Branches: `develop` is current, `main` is far behind (last merged 2026-02-22).

## Commands

```bash
pnpm install
pnpm tauri dev                  # vite on :1420 (strictPort) plus the Rust app
pnpm test:frontend --run        # vitest, one pass; without --run it watches
pnpm build                      # vue-tsc --noEmit (includes the tests), then vite build
pnpm tauri build                # installers; runs pnpm build first

cd src-tauri && cargo check
cd src-tauri && cargo test      # no Rust tests exist yet
cd src-tauri && cargo clippy
```

Needs Rust and the Tauri prerequisites (`README.md`); on Ubuntu 26.04 `sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`. Without them no Rust code compiles, but an old `target/` can make `cargo check` look fine. For a manual check run a local MongoDB, e.g. `docker run --rm -p 27017:27017 mongo:8`, and connect to `localhost:27017` without authentication.

## Architecture

### Rust core (`src-tauri/src`)

- `lib.rs` creates the managed state in `setup`: `AppState` (a `FileRepository` on `<app config dir>/connections.json` with a `CredentialService` for the keyring service `monolens-connections`), `ConnectionHandler` and `TaskManager`. Every command is listed in `generate_handler!` there.
- One command per file in `<module>/commands/<name>.rs`, re-exported by its `mod.rs`.
- Errors cross IPC as `{ kind, message, user_message }`: `DriverError` (drivers), `CommandError` (connector), `TaskError` (tasks). Each implements `Serialize` by hand. A new error variant needs a `user_message`, and the UI shows only that.
- Slow work is a task: a `start_*` command passes its future to `TaskManager.spawn_task` and returns the id; the UI waits with `await_task_result` and cancels with `cancel_task`. The future returns `Result<serde_json::Value, serde_json::Value>`, with errors serialized through `serde_json::to_value(&e)`. Follow `start_connect.rs`.
- Credentials: `get_connections`/`get_connection` never return a password. A command that talks to MongoDB loads it with `hydrate_connection_with_credentials` right before use. The only command that hands a password to the UI is `get_connection_password` (edit dialog).
- `ConnectionHandler.get_or_connect` keeps one driver per connection id for the life of the process. Nothing removes it yet (see Gotchas).
- `DatabaseDriver` is the seam for database work. Add a method to the trait, implement it in `MongoDbOfficialDriver`, then call it from a task command.
- `connections.json` is `{ "version": 1, "connections": { "<id>": … } }`. A change of the stored shape needs a new `STORAGE_VERSION` and a migration in `FileRepository.load_storage`; today a version mismatch is an error.

### Frontend (`src`)

- `main.ts` calls `registerDomains` (creates `CommandRegistry`, `ConnectionServiceIPC`, `ConnectionRepositoryIPC` once and provides them) and then `registerPlugins` (Pinia, shortcuts). Read a service with `useDomain(Class)` in components, or `useDomain(Class, app)` in plugins.
- IPC goes through `ConnectionServiceIPC`: CRUD returns `Result<T>` via `tryCatch`, slow commands use `abortableInvoke` with an `AbortSignal`. `TabViewQuery` and `AppSidebar` still call `invoke` directly; new code uses the service.
- Stores are Pinia setup stores (`defineStore('x', () => {...})`): `connectionStore` (connections, active connection, databases, test state), `tabsStore` (tabs, active tab, history).
- Errors reach the user as `toast.error(extractErrorMessage(e))` (`vue-sonner`). Don't build error boxes.
- Forms use TanStack Form (`@tanstack/vue-form`) with a zod 4 schema as validator (Standard Schema, no adapter) and shadcn-vue's `Field` components (`FieldLabel`, `FieldError`). Bind inputs through `update:model-value`. `ConnectionDialog.vue` is the example.
- Log with `useLogger('<Context>')`, never `console.*`. Never log credentials, not even at `trace`.
- Models live in `src/domains/<area>/models` with an `index.ts` barrel. TypeScript models mirror the Rust structs: camelCase fields (`#[serde(rename_all = "camelCase")]`) and enum values equal to the Rust variant names. Change both sides together.
- Shortcuts: add a command id in `domains/shortcuts/models/commands.ts`, register it in `config/commands.ts`, bind it in `config/default-binding.ts`.
- Theme tokens (OKLCH, dark only, plus `success`, `warning`, `info`) are in `src/styles/default.css`. Use them through Tailwind classes, not raw colours.

## Conventions

- Match the file you edit. Vue components and the table composables use 3-space indentation, stores and domain files 2. Components mostly put `<script setup lang="ts">` first.
- Imports use the `@/` alias for `src`.
- Rust: `thiserror` for error enums, `log::debug!`/`warn!` for logs, `spawn_blocking` around blocking calls such as the keyring.
- Comments are short and explain why, not what.

## Testing

- Every piece of logic gets unit tests, for the regular cases and every edge case you can think of: empty and missing input, boundaries, wrong kinds of values, failing collaborators (MongoDB, keyring, file system).
- Frontend: vitest in happy-dom (the `test` block of `vite.config.ts`), files `*.test.ts` in a `test/` folder next to the code (as `src/utils/queryParser/test/`, `src/composables/table/test/`). Pull logic out of components into composables or `utils` so it can be tested without mounting.
- Rust: `#[cfg(test)] mod tests` in the file, `cargo test`. Abstract MongoDB and the keyring behind traits where a test needs to replace them.
- Untested today, worth covering when touched: `formatCellValue`, `mergeColumnOrder` and the column sizing, `eventToKeyString` and `CommandRegistry`, `tabsStore`, `extractErrorMessage`, `abortableInvoke`; in Rust `TaskManager`, `DriverError::user_message`, `build_connection_string`, `FileRepository`.
- `vue-tsc` type-checks the test files with `noUnusedLocals`, so an unused import in a test breaks `pnpm build`.
- End-to-end checks are manual: `pnpm tauri dev` against a local MongoDB.

## Keep in sync

- Feature change: update its file in `docs/features` (add a building step with the commit, bring "How it works" and "Limits and open points" up to date). A decision also goes into `docs/architecture/decisions.md`.
- New, changed or removed Tauri command: the command table in `docs/architecture/overview.md`, `generate_handler!` in `lib.rs`, and the wrapper in `ConnectionServiceIPC`.
- Rust model change: the TypeScript model in `src/domains/*/models`, and `STORAGE_VERSION` with a migration if `connections.json` changes.
- Connection test stages: the list in `mongo_official_driver.rs` and `_createPendingStages` in `connectionStore.ts`.
- Plan written, its decisions agreed, or built: update its row in `docs/plans/README.md`. A built plan gets a status note at the top (date, commits, deviations, what is still open) and moves to `docs/plans/implemented/` with `git mv`; fix the links to it.
- Setup or build change: update `README.md`.

## Git and GitHub

- Feature branches come off `develop` and are merged through GitHub pull requests into `develop`. Names so far: `feat/<topic>` and, more recently, `feat_<topic>`, `refactor_<topic>`. `develop` goes to `main` by a pull request from time to time.
- Before any push, run the `/code-review` skill on the branch and fix or settle its findings.
- Commit messages are conventional and lowercase: `feat: …`, `fix: …`, `refactor: …`, `chore: …`, `docs: …`, `test: …`. The body explains why and ends with `refers to #<issue>` where an issue exists. Do not add Claude co-author trailers.
- There is no CI. Run `pnpm test:frontend --run`, `pnpm build` and `cargo check` locally before pushing.

## Gotchas

- TypeScript stays on 6.x: `vue-tsc` can't run on TypeScript 7, which no longer ships `lib/tsc`. TypeScript 6 deprecates `baseUrl`, so the tsconfig has `paths` only.
- Run tools with `pnpm exec`, not `npx`: npm refuses to run in this repo, because `devEngines` names pnpm.
- TanStack Table 9 only has the APIs of registered features. The table's features are `documentTableFeatures` in `useDocumentTable.ts`; `row.getVisibleCells()`, for example, needs `columnVisibilityFeature`.
- vue-tsc 3 breaks on a `//` inside a static attribute value (a placeholder like `mongodb+srv://...` made it report errors further down the template).
- The driver pool never drops a driver. After a failed connect or an edited connection, the old MongoDB client stays until restart. Disconnect in the UI only resets frontend state.
- `TabsContainer` keys each tab's view by the *active* tab id, so views multiply and run duplicate queries. `Ctrl+Enter` runs in every mounted view (issue #42), and `CommandRegistry.unsubscribe` uses `findIndex(subscriber)`, which calls the subscriber. Details in `docs/features/tabs.md` and `shortcuts.md`.
- `TabViewQuery` queries `connectionStore.activeConnection`, not the tab's own connection, and tabs survive a switch of connection.
- The connection field `uri` holds a host. The driver always builds `mongodb://<host>:<port>/?authSource=<db>`; SRV and full connection strings don't work.
- TypeScript `ConnectionType.ShardedCluster` is `"SharedCluster"`, Rust expects `ShardedCluster`. Harmless only because the UI always sends `Standalone`.
- `ConnectionServiceIPC.saveConnection`/`saveConnections` call commands that don't exist. `ConnectionRepositoryIPC` is registered and unused.
- Commands reach the keyring by downcasting the repository to `FileRepository`. Another repository type fails with "Unsupported repository type".
- The log level is `Debug` in release builds too. `ConnectionDialog` logs form values, password included, at `trace`.
- Query filters cross IPC as extended JSON. bson turns `{ $oid }`, `{ $date: "<RFC 3339>" }` and the number wrappers into BSON types; anything it can't read stays a plain object and silently matches nothing.
- On Linux the keyring needs a Secret Service (GNOME Keyring, KWallet). keyring 4 talks to it through `zbus`; there is no keyutils cache any more.
- `cargo clippy` reports 15 warnings in code that predates the revival (needless borrows, missing `Default`, an 8-argument command, …). Fix them where you touch the code.
- Change the pinned pnpm with `pnpm self-update <version>` inside the repo, never by hand, or `--frozen-lockfile` fails (pnpm records its version in the lockfile).
- `gh` is not installed on this machine. The repo is public: read issues and pull requests through `https://api.github.com/repos/WebXIO/monolens/issues` and `/pulls`.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.
